# SHARP: Sharp Monocular View Synthesis — Project Description

## 1. Overview

**SHARP** (Sharp Monocular View Synthesis in Less Than a Second) is a research project by Apple Inc. (2025) that performs **photorealistic view synthesis from a single RGB image**. Given one photograph, SHARP predicts a **3D Gaussian Splatting (3DGS)** representation of the scene in under one second via a single feedforward neural network pass. The resulting 3D Gaussian representation can be rendered in real-time from nearby camera viewpoints, producing high-resolution photorealistic images.

The representation is **metric** (absolute scale), supports **metric camera movements**, and uses the **OpenCV coordinate convention** (X right, Y down, Z forward).

### Key Metrics
- **Inference time**: < 1 second on standard GPU
- **Quality**: Reduces LPIPS by 25–34% and DISTS by 21–43% vs. best prior models
- **Speed**: 3 orders of magnitude faster than prior methods
- **Zero-shot generalization**: Robust across multiple datasets without fine-tuning

### Paper
- **Title**: Sharp Monocular View Synthesis in Less Than a Second
- **Authors**: Lars Mescheder, Wei Dong, Shiwei Li, Xuyang Bai, Marcel Santos, Peiyun Hu, Bruno Lecouat, Mingmin Zhen, Amaël Delaunoy, Tian Fang, Yanghai Tsin, Stephan R. Richter, Vladlen Koltun
- **arXiv**: [2512.10685](https://arxiv.org/abs/2512.10685)
- **Project Page**: [https://apple.github.io/ml-sharp/](https://apple.github.io/ml-sharp/)

## 3. Installation & Usage

### Prerequisites
- Python 3.13 (recommended)
- CUDA-capable GPU (for rendering; not required for prediction)

### Setup
```bash
# Create virtual environment
conda create -n sharp python=3.13
conda activate sharp

# Install dependencies
pip install -r requirements.txt

# Verify installation
sharp --help
```

### CLI Commands

#### Prediction (Image → 3D Gaussians)
```bash
# Basic usage: single image
sharp predict -i /path/to/image.jpg -o /path/to/output/

# Directory of images
sharp predict -i /path/to/images/ -o /path/to/output/

# With custom checkpoint
sharp predict -i /path/to/image.jpg -o /path/to/output/ -c /path/to/checkpoint.pt

# With rendering (requires CUDA)
sharp predict -i /path/to/image.jpg -o /path/to/output/ --render

# Specify device
sharp predict -i /path/to/image.jpg -o /path/to/output/ --device cuda
sharp predict -i /path/to/image.jpg -o /path/to/output/ --device cpu
sharp predict -i /path/to/image.jpg -o /path/to/output/ --device mps

# Verbose logging
sharp predict -i /path/to/image.jpg -o /path/to/output/ -v
```

#### Rendering (3D Gaussians → Video)
```bash
# Render from PLY file
sharp render -i /path/to/output/scene.ply -o /path/to/renderings/

# Render from directory of PLY files
sharp render -i /path/to/output/ -o /path/to/renderings/
```

### Model Checkpoint
- **Default URL**: `https://ml-site.cdn-apple.com/models/sharp/sharp_2572gikvuh.pt`
- The model is **auto-downloaded** on first run and cached at `~/.cache/torch/hub/checkpoints/`
- Alternatively, download manually and specify with `-c`

### Output Format
- **3DGS PLY files**: Compatible with standard 3DGS renderers
- **Coordinate system**: OpenCV convention (X right, Y down, Z forward)
- **Scene center**: Roughly at (0, 0, +z)
- **Note**: Third-party renderers may require scaling/rotation to re-center the scene

## 4. Architecture Overview

SHARP is a **feedforward neural network** that maps a single RGB image to a set of 3D Gaussians. The architecture consists of five interconnected sub-modules orchestrated by `RGBGaussianPredictor`.

### 4.1 High-Level Pipeline

```
Input RGB Image
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│                   RGBGaussianPredictor                      │
│                                                             │
│  ┌──────────────┐    ┌──────────────────────────────────┐   │
│  │ Monodepth    │    │  Gaussian Decoder                │   │
│  │ (Depth Net)  │    │  (Feature Network)               │   │
│  └──────┬───────┘    └──────────────┬───────────────────┘   │
│         │                          │                         │
│         │    ┌─────────────────────┼──────────────┐         │
│         │    ▼                     ▼              │         │
│         │ ┌──────────────────────────────────────┐│         │
│         │ │  DirectPredictionHead                ││         │
│         │ │  (Predicts delta values)             ││         │
│         │ └──────────────┬───────────────────────┘│         │
│         │                │                         │         │
│         │                ▼                         │         │
│         │    ┌──────────────────────────────────┐  │         │
│         │    │  GaussianComposer                │  │         │
│         │    │  (base_values + deltas → Gauss)  │  │         │
│         │    └──────────────┬───────────────────┘  │         │
│         │                   │                       │         │
│         ▼                   ▼                       │         │
│  ┌──────────────┐    ┌──────────────────────────┐   │         │
│  │ Initializer  │    │  Depth Alignment         │   │         │
│  │ (Base Gauss) │    │  (Learned scale map)     │   │         │
│  └──────────────┘    └──────────────────────────┘   │         │
│                                                     │         │
└─────────────────────────────────────────────────────┘         │
                    │                                            │
                    ▼                                            │
              Gaussians3D (metric space)                         │
                    │                                            │
                    ▼                                            │
              PLY file / Real-time rendering                     │
└────────────────────────────────────────────────────────────────┘
```

### 4.2 Sub-Module Details

#### 4.2.1 Monodepth Module (`models/monodepth.py`)

Predicts monocular depth/disparity from the input image and produces multi-resolution feature maps for downstream use.

**Components:**
- **`AffineRangeNormalizer`**: Maps input images from `[0, 1]` to `[-1, 1]`
- **`SlidingPyramidNetwork`**: Multi-resolution ViT-based encoder (see §4.3)
- **`MultiresConvDecoder`**: Fuses multi-resolution features (see §4.4)
- **5-layer convolutional head**: Outputs single-channel disparity map

**`MonodepthWithEncodingAdaptor`** wraps the transformer to return:
1. The disparity output
2. Intermediate encoder feature maps
3. Intermediate decoder feature maps

By default, all monodepth weights are **frozen** during training.

#### 4.2.2 Gaussian Decoder (`models/gaussian_decoder.py`)

The main image-to-image network that produces texture and geometry features from monodepth features.

**`GaussianDensePredictionTransformer`**:
- Takes `input_features` (image + normalized disparity from initializer) and `encodings` (from monodepth)
- Uses `MultiresConvDecoder` to decode multi-resolution features
- Applies `SkipConvBackbone` for skip connections from input image
- Fuses using `FeatureFusionBlock2d`
- Produces two separate feature streams:
  - **Texture features** (32-dim): color, opacity, scale, quaternion deltas
  - **Geometry features** (32-dim): mean vector deltas
- Final stride: 1 or 2 (upsamples if stride=1)

**`ImageFeatures`** (NamedTuple): Holds `texture_features` and `geometry_features`.

#### 4.2.3 Prediction Head (`models/heads.py`)

**`DirectPredictionHead`** converts decoded features into delta values for Gaussian attributes:

| Head | Output Channels | Attributes |
|------|----------------|------------|
| `geometry_prediction_head` | 3 × num_layers | x, y, z deltas |
| `texture_prediction_head` | 11 × num_layers | scale×3, quaternion×4, color×3, opacity×1 |

**Total: 14 channels per layer** (3 means + 3 scales + 4 quaternions + 3 colors + 1 opacity).

Both heads use **zero-weight initialization** for stable training.

#### 4.2.4 Initializer (`models/initializer.py`)

Creates **base Gaussian values** from the input image and monodepth disparity. These serve as the starting point that the network refines via delta predictions.

**Output shape**: `batch × dim × num_layers × base_height × base_width`

| Attribute | Shape | Initialization Strategy |
|-----------|-------|------------------------|
| `mean_x_ndc` | `(B, 1, N, H, W)` | NDC grid coordinates from image grid |
| `mean_y_ndc` | `(B, 1, N, H, W)` | NDC grid coordinates from image grid |
| `mean_inverse_z_ndc` | `(B, 1, N, H, W)` | Disparity from monodepth |
| `scales` | `(B, 1, N, H, W)` | Derived from inverse disparity × scale factor |
| `quaternions` | `(B, 4, N, H, W)` | Identity `[1, 0, 0, 0]` (no rotation) |
| `colors` | `(B, 3, N, H, W)` | Avg-pooled input image or gray (0.5) |
| `opacities` | `(B, 1, N, H, W)` | `min(1/num_layers, 0.5)` |

**Depth initialization options**:
- `surface_min`: Max-pooled disparity (nearest surface)
- `surface_max`: Min-pooled disparity (farthest surface)
- `base_depth`: Uniform plane at `base_depth` (default 10.0)
- `linear_disparity`: Linearly spaced disparity planes

Depth is rescaled per-batch using `depth_factor = 1.0 / min_depth`, and a `global_scale = 1.0 / depth_factor` is returned for later unscale in the composer.

#### 4.2.5 Gaussian Composer (`models/composer.py`)

Combines base Gaussian values with predicted delta values to produce the final 3D Gaussians.

**Forward pass:**
1. **Upsample deltas** if coarser than base values
2. **Mean activation**: NDC coordinates + delta offsets; z uses inverse-softplus for numerical stability; converts NDC to metric coordinates
3. **Scale activation**: `base_scale × sigmoid(constant_a × delta + constant_b) + min_scale`, clamped to `[min_scale, max_scale]`
4. **Quaternion activation**: Simple addition with delta factor
5. **Color activation**: Inverse activation → add delta → forward activation (default: sigmoid); converts to linearRGB
6. **Opacity activation**: Inverse sigmoid → add delta → sigmoid
7. **Flatten** from `(B, C, N, H, W)` → `(B, N×H×W, C)`
8. **Apply global_scale** to convert from normalized NDC to metric space

#### 4.2.6 Depth Alignment (`models/alignment.py`)

A **learned module** that refines monodepth predictions using ground truth depth during training.

**`LearnedAlignment`**:
- Small UNet (encoder + decoder)
- Takes concatenated `[monodepth, gt_depth]` (inverted to disparity) and optionally monodepth decoder features
- Outputs per-pixel **scale map** that multiplies the monodepth
- Uses `exp` activation (positive scale values)
- Initialized with bias = 1.0 (identity) and zero weights

#### 4.2.7 Main Predictor (`models/predictor.py`)

**`RGBGaussianPredictor`** orchestrates the entire forward pipeline:

```
monodepth        depth    # Both are metric
    |              |
    +------+-------+
           |
    +-------+--------+     # Optionally align monodepth to GT depth
    | depth_alignment|     # with learned scale map
    +-------+--------+
           |
           v
  monodepth (aligned)
           |
     +-----+----+
     | init_model|         # Normalize depth, compute base gaussians
     +-----+----+
           |
           v
   init_output         # Features, base gaussians, global scale
           |
     +-----+-----+
     | main network|     # Compute delta values
     +-----+-----+
           |
           v
       delta_values
           |
    +-------+---------+
    | gaussian_composer|  # Add delta to base, unscale
    +-------+---------+
           |
           v
       gaussians       # Final 3D Gaussians in metric space
```

## 5. Encoder Architectures

### 5.1 Sliding Pyramid Network (SPN) — `models/encoders/spn_encoder.py`

Multi-resolution ViT-based encoder inspired by **Depth Pro** (Bochkovskii et al., ICLR 2024).

**Architecture:**
1. Creates a **3-level image pyramid**: full (1536), middle (768), low (384)
2. Splits each level into **overlapping patches** using sliding window:
   - 5×5 patches of 384×384 at highest resolution (25% overlap) → **25 patches**
   - 3×3 patches of 384×384 at middle resolution (50% overlap) → **9 patches**
   - 1×1 patch at lowest resolution → **1 patch**
   - Total: **35 patches** (or 21 without overlap)
3. All patches run through a **patch encoder ViT** (DINOv2-L/16)
4. Merges overlapping patches back into spatial feature maps
5. Lowest-resolution image runs through an **image encoder ViT**
6. Upsamples all feature maps and fuses via `ConvTranspose2d` + `Conv2d` projection
7. Produces **5 multi-resolution feature maps**: `[256, 512, 1024, 1024, 1024]`

**Helper functions:**
- `split()`: Creates overlapping sliding window patches
- `merge()`: Merges patches back, removing overlapping borders

### 5.2 Vision Transformer Encoder — `models/encoders/vit_encoder.py`

**`TimmViT`**: Wraps `timm.models.VisionTransformer` as ViT backbone.
- Extracts intermediate layer features via `intermediate_features_ids`
- `reshape_feature()`: Discards class token, reshapes 1D tokens to 2D spatial maps
- **Default preset**: DINOv2-L/16 @ 384×384 (1024-dim, 24 layers, 16 heads)

### 5.3 Multi-Resolution Convolutional Decoder — `models/decoders/multires_conv_decoder.py`

Fuses multi-resolution encoder features into a single high-resolution feature map (DPT-style).

**`MultiresConvDecoder`**:
- Projects each encoder level's features to common decoder dimension via 1×1/3×3 convs
- Fuses from lowest to highest resolution using `FeatureFusionBlock2d` (residual blocks + optional transposed conv upsampling)
- **Default decoder dims**: `[128, 128, 128, 128, 128]`

## 6. Data Flow: Input Image → Output PLY

```
1. INPUT: RGB image (any resolution, e.g., 4000×3000)
   │
   ▼
2. PREPROCESSING (cli/predict.py: predict_image)
   - Load via io.load_rgb() → extract focal length from EXIF
   - Normalize to [0, 1], convert to tensor (C, H, W)
   - Resize to internal resolution: 1536×1536
   - Compute disparity_factor = f_px / width
   │
   ▼
3. FORWARD PASS (RGBGaussianPredictor.forward)
   a. Monodepth: image → disparity map + multi-resolution features
   b. Depth alignment (optional): align disparity to GT depth
   c. Initializer: (image, aligned_disparity) → base Gaussians + feature_input
   d. GaussianDecoder: (feature_input, monodepth_features) → ImageFeatures
   e. DirectPredictionHead: ImageFeatures → delta values (14 × num_layers channels)
   f. GaussianComposer: base_values + deltas → Gaussians3D (in NDC space)
   │
   ▼
4. POSTPROCESSING
   - Build intrinsics matrix (f_px, principal point)
   - unproject_gaussians(): NDC → Euclidean/world coordinates
   │
   ▼
5. SAVE (utils/gaussians.py: save_ply)
   - Convert: mean_vectors → xyz, singular_values → log(scales),
     quaternions → rot_0..3, colors → linearRGB→sRGB→SH degree-0,
     opacities → inverse_sigmoid → opacity
   - Store metadata: intrinsic (9 values), extrinsic (identity),
     image_size, frame count, disparity range, color_space, version
   - Write PLY file via plyfile library
```

## 9. Key Constants & Conventions

### 9.1 Shapes & Dimensions

| Constant | Value | Location |
|----------|-------|----------|
| Internal resolution | 1536 | `predict.py`, `spn_encoder.py` |
| Patch size | 384 | `spn_encoder.py` |
| Gaussian channels/layer | 14 | `heads.py` |
| Default num_layers | 2 | `params.py` |
| Default stride | 2 | `params.py` |
| Default focal length | 512 px | `gaussians.py` |
| Default resolution | 640×480 | `gaussians.py` |
| Depth clamp max | 50.0 m | `vis.py` |

### 9.2 Coordinate Conventions

- **NDC space**: x, y ∈ [-1, 1], where (-1, -1) is top-left, (1, 1) is bottom-right. Z is inverse depth.
- **OpenCV camera**: Z points forward, X right, Y down.
- **Scene center**: Roughly at (0, 0, +z).
- **PLY format**:
  - Colors: Spherical harmonics degree-0 (SH0 = 0.5 + sqrt(1/(4π)) × RGB)
  - Scales: Stored as log(singular_values)
  - Quaternions: w-xyz order (w first)
  - Opacity: Inverse-sigmoid logits
  - Color space: linearRGB internally, converted to sRGB for PLY export

### 9.3 Supported Image Formats

All standard formats plus HEIC (via `pillow-heif`).

## 10. Rendering Pipeline

Rendering requires a **CUDA GPU** (gsplat renderer does not support CPU/MPS).

### 10.1 Trajectory Types (`utils/camera.py`)

| Type | Description |
|------|-------------|
| `swipe` | Horizontal sweep across the scene |
| `shake` | Small oscillating movement |
| `rotate` | 360° rotation around scene center |
| `rotate_forward` | Rotation with forward camera movement |

### 10.2 Rendering Steps

1. Load PLY file → `Gaussians3D` + `SceneMetaData`
2. Create `PinholeCameraModel` with intrinsics
3. Generate camera eye trajectory
4. For each frame:
   - Compute camera info (intrinsics + extrinsics)
   - Render via `GSplatRenderer` → RGB + depth + alpha
   - Convert linearRGB→sRGB, scale to [0, 255] uint8
5. Write frames to MP4 via `VideoWriter`

## 14. Troubleshooting

### Rendering fails on non-CUDA devices
The gsplat renderer requires CUDA. Prediction works on CPU, MPS, and CUDA, but `--render` and the `sharp render` command require a CUDA GPU.

### Model download fails
Manually download the checkpoint:
```bash
wget https://ml-site.cdn-apple.com/models/sharp/sharp_2572gikvuh.pt
sharp predict -i image.jpg -o output/ -c sharp_2572gikvuh.pt
```

### PLY files appear rotated/scaled incorrectly in third-party renderers
SHARP follows OpenCV convention (X right, Y down, Z forward) with scene center near (0, 0, +z). Third-party renderers may need rotation/scaling adjustments. Apply appropriate transformation to re-center the scene.

### HEIC images not loading
Ensure `pillow-heif` is installed (included in `requirements.txt`).

### Out of memory during inference
Reduce batch size or use `--device cpu` (slower but lower memory). The internal resolution is fixed at 1536×1536.
